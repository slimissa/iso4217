## What changed

Four changes. Three were defects surfaced after the v1.7.7
verification; the fourth was found while preparing the patch.

### 1. `check_country_codes.py` added to the release gate

`docs/JOINS.md` claimed the check ran "in the release gate and in
CI"; only CI ran it. The gate ran fourteen checks; CI's fast
workflow ran fifteen. Added as the fifteenth gate step, after
`check_registry_freshness.py` and before `check_cross_language.sh`.
This restores the invariant added in v1.7.6: the gate must include
every check that runs in CI's fast workflow.

### 2. `BrokenPipeError` on piped output

`wrappers/python/iso4217_cli.py` raised an uncaught
`BrokenPipeError` when piped into a reader that closes early
(`head`, `less`, `grep -q`). The fix has two parts:

- The subcommand body is now `_run()`; `main()` wraps it in a
  try/except and flushes stdout **inside** the try, so the closed
  pipe is caught at flush time rather than at interpreter shutdown.
- On `BrokenPipeError`, `_silence_broken_pipe()` redirects stdout
  to `/dev/null` via `os.dup2` before returning `EXIT_BROKEN_PIPE`
  (141). Without the redirect, the interpreter's final flush would
  raise a second `BrokenPipeError` and print
  `Exception ignored ...` to stderr — the failure mode the fix
  exists to prevent.

The handler lives in `main()`, not under
`if __name__ == "__main__"`, because the installed `iso4217`
command is a `console_scripts` wrapper that calls `main()`
directly. Putting it only in `__main__` would leave the installed
entry point unfixed.

Exit code 141 (128 + SIGPIPE) matches the convention Unix tools
follow. A shell pipeline that ends in `head` will still see exit 0
because `$?` reflects the last command in the pipe; the 141 is
visible when the CLI is invoked directly or under `pipefail`.

### 3. `tools/export_aggregated.py` rejected `Unreleased` headings

`release.sh` writes `## [X.Y.Z] — Unreleased` into `CHANGELOG.md`
at the start of a release cycle, before the version is dated.
`export_aggregated.py` treated that as a malformed date and failed
`--check` with exit 2 — meaning the release script's own gate could
not run between writing the heading and dating it.

`Unreleased` is now skipped: a version that has not been released
has no row in `coverage_timeline.parquet` until `release.sh`
replaces the word with the release date, which is when the version
first appears.

### 4. `README.md` rewritten against the v1.7.7 tree

The prior README pinned v1.7.3, described a nine-artifact
eleven-check release, carried the wrong ADR numbers, claimed
packages were published to PyPI/npm/crates.io, and said
`axes.json` was read by the version check. None of that was true
at v1.7.7. The README now matches the tree.

## Notes

- **The two pipe tests are stronger than they look.**
  `test_closed_reader_exits_141_quietly` is parameterized over two
  invocation paths (`main()` and the console-script entry point) and
  asserts the return code is exactly 141.
  `test_working_pipe_is_unaffected` guards against the fix
  regressing normal output. Both spawn subprocesses with real
  pipes; neither is a mock that could pass while the fix was
  absent.
- **The README rewrite was deferred from v1.7.7.** It is the
  largest diff in this release by line count (1062 lines) but the
  smallest by content: no claim in the new README is unsupported
  by the tree, and every count it states is checked by a gate
  step or a test.
