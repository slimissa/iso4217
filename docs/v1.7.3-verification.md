## 8.11 — Manifest audit

New in v1.7.3. The `--audit` mode iterates every manifest entry
against the current tree.

The audit is diagnostic — a version-string claim fails for any
entry whose version has been superseded. Both `1.7.1` and `1.7.2`
show partial failure for their version-string claims; `1.7.3`
shows full pass because the tree is at `1.7.3`. The tool exits 1
on any failure; this is not a gate, it's a check a maintainer runs
before committing new claims.

## What changed since v1.7.2

**Added:**
- `check_manifest_has_version` precondition. Fails two seconds in
  when the manifest has no entry for the version being released.
  The v1.7.2 release caught the same condition at gate time, after
  version bump and artifact regeneration.
- `--audit` mode in `tools/check_release_claims.py`. Iterates every
  manifest entry; reports per-entry pass counts against the current
  tree.
- `RELEASE_PATTERN.md` operator-hygiene rule 6c — "Manifest claims
  describe state, not intent," sourced from ISO 3166 v1.6.7.
- `RELEASE_PATTERN.md` gate-block shape rule under invariant 5.
  Names per-check capture and subshell-with-set-e as valid; the
  bare brace group as invalid.

**Fixed:**
- `check_release_claims.py` had a duplicate `version` positional in
  its argparse. `--audit` never reached its handler; the gate
  passed `None` to the manifest lookup. Fixed in `dd9be8e` by
  making `version` optional (`nargs="?"`) and running the `--audit`
  branch before the version lookup.

## Known gaps

- `code_lifetime.from` remains `null` for all 135 withdrawn entries
- `axes.json` declared but not consumed by `check_version_consistency.py`
- The audit reports failures for superseded entries by design; the
