# v1.6.0 candidates

Deferred decisions and improvements that did not fit the v1.5.x line.

## Registry structure

- **`standard` field on every entry.** Permits filtering "give me only
  ISO 4217 entries" with a single field check instead of a top-level
  array choice. Deferred because it is a schema addition, which
  requires a minor-version bump. Revisit when the ISO 3166 registry
  ships and the shared shape between registries becomes the design
  constraint.

## Data quality

- **Consolidate the three Mexican entries.** `MXN` (active), `MXP`
  (withdrawn ISO code), and `MXN_OLD` (withdrawn synthetic) all share
  numeric 484. Two withdrawn entries for the same currency lineage is
  a data-quality wart. Consolidating requires deciding whether the
  synthetic identifier or the ISO-assigned code is the canonical
  withdrawn form, and then updating the schema and every test.
  Deferred from v1.5.1 because it is a data change, not documentation.
