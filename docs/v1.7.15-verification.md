## What changed

Five findings from the v1.7.11 audit, and three release-script
hygiene items from v1.7.14's verification doc. No data changes; no
schema changes.

### Fixed — the amendment monitor exits 3 when it cannot read the page (F9)

`tools/check_amendments.py` exited 0 on every fetch failure and
reported the hard-coded 179 as if it were live data. `parse_failed`
— the state the redesigned SIX page produces today — did the same.
The script now:

- exits 3 when the page cannot be fetched or parsed;
- retries transient failures (timeouts, connection errors, HTTP
  429/5xx) three times, first at 5 s then at 10 s;
- turns an uncaught exception into exit 2 instead of Python's
  default 1 (which means "new amendment");
- adds `determined` and `simulated` fields to the JSON output;
  `new_amendment_detected` is `null` when undetermined.

The workflow dropped `continue-on-error`, captures the exit code
explicitly, opens or updates a `monitor-blind` issue on exit 3,
opens an "amendment N detected" issue on exit 1, and turns the run
red on any exit other than 0 or 1.

### Fixed — the parser reads the number from the download link (F9)

The redesigned SIX page names the amendment number only in the file
name of the download link: `dl-currency-iso-amendment-180.pdf`.
A third pattern (`amendment[-_](\d{1,3})\.pdf`) reads it, and the
`Number` word is accepted after "Amendment". The live monitor now
reads 180.

### Fixed — `monitor-amendments.yml` declared no permissions (F8)

The repository default token is `read`. The job's `issues.create`
call could not have worked without an explicit `permissions:` block.
Added `contents: read` and `issues: write`.

### Fixed — CI path filters omitted guarded files (F4)

`validate.yml` ran only when a listed path changed; the list
omitted `examples/**`, `scripts/**`, `tools/export_aggregated.py`,
`tools/check_*.py`, and the four derived Parquet files. A push
that edited `examples/stores-200/analyze.py` did not run the test
that guards it. All `paths:` filters are removed on both `push` and
`pull_request`. The median `validate.yml` run is 1.1 min; no
fallback is needed.

### Fixed — one job per hygiene check (F24)

"Country codes resolve" ran three checks as steps. Each check now
has its own job; the existing job keeps its name and identity, so
any branch-protection rule that names it continues to work. The
workflow header no longer states a count.

### Fixed — three release-script rough edges

- `commit_and_push` runs `git --no-pager diff --cached --stat`, so
  the release no longer blocks on an interactive pager.
- `check_no_orphan_variables` called an undefined `die`; it now
  calls `fail`.
- `print_plan` lists all 17 gate steps in `run_gate` order.
  Previously it listed 15.

### Added — supply-chain pins (F7)

All six workflow actions are pinned by commit SHA with a version
comment. `requirements-ci.txt` pins the CI Python dependencies
(`duckdb==1.5.6` exactly, because the demo test asserts specific
numbers); every `pip install` reads it. `--upgrade pip` and
`npm install` are gone. `.github/dependabot.yml` covers
`github-actions`, `pip`, `gomod`, and `cargo`.

### Added — `--simulate` and the `simulate` dispatch input

`check_amendments.py --simulate undetermined|new-amendment` and a
matching `workflow_dispatch` input exercise both alert paths
without contacting SIX.

## The registry was born behind Amendment 180

The v1.7.11 audit's F9 said the amendment monitor "can go blind and
stay green". It did.

This registry was created on 2026-07-29 (v1.0.0) at amendment 179,
ten months after SIX dated amendment 180 (2025-09-22). The monitor
was added on 2026-08-26 (`8ff385e`). It fetched the SIX page, failed
to parse it (`fetch_status: parse_failed`: the redesigned page names
the amendment number only in the download link's file name), fell
back to the hard-coded 179, and exited 0.

Two failures stacked: the registry was created behind, and the
monitor meant to catch exactly that could not read the page.

The monitor's outcome history is not recoverable from retained
logs. `gh run view --log` returns empty for the eight successful
runs and `log not found` for the three failed ones on 2026-08-26.
What is confirmed is that it reported `success` for seven
consecutive weeks on a page it cannot parse, and no issue about
amendment 180 was ever filed.

v1.7.15 does not fix a latent bug; it fixes a monitor that has
reported success on a check it could not perform for its whole life.
That is the release's reason to exist, ahead of any other finding.

### `last_verified` is stale

`last_verified` in `iso4217.json` reads `2026-07-29`, the v1.0.0
date: it was set at creation and has not changed since. The tree
reflects amendment 179 while SIX dated amendment 180 on
2025-09-22, so the field's meaning, "last confirmed correct
against the primary source", was not true when it was written.

The Amendment 180 release corrects it, along with `meta.amendment`,
`meta.amendment_date`, `source.last_amendment_applied` and
`source.last_amendment_date`. The v1.7.15 monitor makes the next
drift in the amendment number visible on the Monday it happens. It
does not maintain `last_verified`: nothing automatic writes that
field, so how it gets set is a separate decision.

## Known limits

### A7's Validate Registry was cancelled, not failed

Two commits pushed 24 seconds apart (`bbbefe1` and `98c3608`)
triggered two `Validate Registry` runs. GitHub's concurrency group
`validate-registry-refs/heads/main` cancelled the older one. The
annotation reads `Canceling since a higher priority waiting request
for validate-registry-refs/heads/main exists`. The rerun was green.

This is a new consequence of F4's fix: before A5, a docs-only
commit did not trigger `Validate Registry` at all, so consecutive
docs pushes could not collide. After A5, every push triggers it,
and two pushes close together will cancel the older run. That is
the correct behaviour of a strict test gate, but it is new.

### A1's commit boundary slipped

The commit for F8 (`48104bb`) carried A2a's workflow rewrite, not
just the 5-line permissions block, because A2a wrote to the same
file before A1 was staged. The end state is correct and the batch
was pushed intact; only the commit boundaries differ.

Future releases should commit each script before running the next
when two scripts target the same file. Rule 6b, in a new shape: an
edit landed, but in the wrong commit.

### The pager fix is tested by harness, not by a real run

`--dry-run` exits before `commit_and_push`, and the orphan check
reaches `fail` only when it finds an orphan. v1.7.15 is the first
release that runs with `--no-pager` — see the release log's staged
stat.

### No branch protection on `main`

Pre-flight §7 returned 404 for `/branches/main/protection` and `[]`
for `/rulesets`. Nothing is required today. If protection is ever
added, name all ten jobs of "Version and Hygiene" (including
"README drift" and "Verification docs complete") and the
`validate.yml` jobs. `tests/test_ci_job_layout.py` pins the job
names so a rename cannot slip through.

### `dtolnay/rust-toolchain` is SHA-pinned to the action, not the compiler

The action downloads whatever `stable` resolves to at run time. An
explicit `toolchain:` input would pin the compiler. Dependabot
cannot bump a branch pin; re-pin by hand (`resolve_pins.sh`).

### `check_release_claims.py --audit` reports 79 failures across 14 entries

Every one is expected: manifests record what each version's tree
contained, not what today's tree contains. Only the release
version's entry is load-bearing.

### Deferred F7 items

`SECURITY.md`, `CODEOWNERS`, and a Rust `Cargo.lock`.

### The release gate is not pinned

CI installs `requirements-ci.txt`; the gate runs against whatever
your venv holds.

### Pre-existing, untouched

`load_registry_amendment` returns 0 when `source.last_amendment_applied`
is missing. `date_checked` uses the local date, not UTC (v1.7.14
fixed the writes into data, not this print). A fatal exit 2 turns
the job red but opens no issue.

### Actions log retention

GitHub keeps logs for at most 90 days on a public repository; the
monitor's history is not recoverable past that. If its outcome
history must outlive the window, each run has to write its result
somewhere tracked; not in v1.7.15.

### The monitor reaches the page through two 301 redirects

`currency-iso.org` → `six-group.com` (twice). `urllib` follows them
or the run exits 3, which is now loud. Pointing `SIX_AMENDMENTS_URL`
at the final URL is a small separate change.

### `update_from_iso.py --apply` writes `last_verified` without advancing the amendment

`:451` and `:571-572` set `last_verified` from today's date and
`last_amendment_applied` from the registry's own current value.
`meta.amendment`, `meta.amendment_date` and
`source.last_amendment_date` are never written. Until v1.8.2
constrains it, do not use `--apply` for an amendment.

### F11 remains open

`validate.py` passes with its schema layer skipped when no
`schema.json` sits beside `--registry`. Rule 7 cites four instances;
the fifth lands in v1.8.2.
