## What changed

Four findings from the v1.7.11 audit, and operator-hygiene rule 7.
No data changes; no schema changes.

### Fixed — a skipped test is a failure (F3)

Without pandas, 8 tests were skipped and `pytest tests/` still exited
0, so CI and the release gate could be green without them — and
without the demo test when duckdb was absent. CI now installs pandas,
and both CI and the gate run `pytest tests/` with a new
`--fail-on-skip` option in `tests/conftest.py`; the allowed number of
skips is 0. A plain `pytest tests/` stays lenient so a contributor
without pandas can still run the rest.

### Fixed — the release commit could contain unexpected files (F25)

`commit_and_push` ran `git add -A` and committed without showing what
was staged. It now:

- aborts on any untracked, non-ignored file before staging;
- prints `git diff --cached --stat` before committing;
- aborts (unstaging first) if any staged path is not a plain
  modification.

### Fixed — dates were on the local clock (F19)

The release date, `meta.updated`, the CHANGELOG date, `last_verified`,
`withdrawn_date`, and the freshness and validation comparisons now use
UTC. The one-day tolerance in `check_registry_freshness.py` stays as a
belt. Filenames and report timestamps stay local on purpose.

### Fixed — tag messages dropped their section headings (F17)

`git tag -a -m` strips every line beginning with `#`, so `### Fixed`
and `### Added` were silently missing from every tag message. The
message is now written to a file, tagged with
`-F <file> --cleanup=whitespace`, read back from the tag object, and
compared; a mismatch deletes the local tag and stops before the push.
The stale "nine artifacts" count in `RELEASE_PATTERN.md` is removed.

### Added — operator-hygiene rule 7

`RELEASE_PATTERN.md` rule 7: *a check that cannot run must fail, not
pass.* Cited by version from v1.7.12 (`poll_ci`), v1.7.13
(`check_cross_language.sh`), and v1.7.14 (pytest skips). The hygiene
rules are now ordered 6, 6c, 6d, 7 — 6c precedes 6d, and its heading
has no stray `**`.

## Known limits

### Open findings, scheduled for v1.7.15

- **F4** — `validate.yml`'s path filters omit `examples/**`,
  `scripts/**`, `tools/export_aggregated.py`, `tools/check_*.py`,
  and the four derived Parquet files.
- **F7** — actions pinned by tag, not SHA; unpinned pip installs;
  `dtolnay/rust-toolchain@stable`; no Dependabot.
- **F8** — `monitor-amendments.yml` has no `permissions:` block and
  creates issues.
- **F9** — the amendment monitor exits 0 on network or parse failure,
  so it can go blind and stay green. Fifth instance of hygiene rule 7.
- **F24** — CI job names no longer match what runs.

### Release-script hygiene, scheduled for v1.7.15

- `commit_and_push` runs `git diff --cached --stat` without
  `--no-pager`, so the release blocks on the pager when run
  interactively. Non-interactive shells are unaffected. This release
  hit it; the operator pressed `q` and the release continued.
- `die` is called in `check_no_orphan_variables` but never defined.
  The check still aborts, with `command not found`.
- `print_plan` lists 15 of the 17 gate steps (the two missing are
  `check_readme_drift.py` and `check_verification_doc.py`).

### First live use

The F25 staged-status check, the F17 tag read-back, and the F19 UTC
date fired for the first time in this release. They are covered by
tests against real temporary git repositories; this release was the
first against the actual remote.

### The tests skip on Windows

`tests/test_check_cross_language.py`, `test_release_commit_and_push.py`,
`test_release_tag.py`, and `test_utc_dates.py` skip on Windows. The
release gate is POSIX-only anyway.
