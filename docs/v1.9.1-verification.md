## What changed

The text below is the CHANGELOG section for this release, verbatim.

The gate learns to fail. The fifth-pass audit (`docs/audits/fifth-pass.md`) forced four gate tools to exit 0 and all
1,421 tests stayed green. This release adds the tests that make every gate tool prove it can fail (P5-02), the rule that
requires them (R10), a check that keeps `docs/AUDIT.md` true (AD), CI and gate parity (P5-05), the fix for the
`check_release_claims.py --audit` crash (P5-08) and `vendor_iso3166.py --check-upstream` (F31). No registry data change;
no schema change. The other audit findings are queued for later releases.

### Fixed

- **`check_release_claims.py` crashed on Parquet files (P5-08).** `check_claim` read every claimed file as UTF-8 before
  looking at the claim's shape, so the v1.7.4 existence claims on `.parquet` files raised `UnicodeDecodeError`, and so did
  `--audit` (hygiene rule 6c's mechanism) and `check_release_claims.py 1.7.4`, exiting 1 like a finding. An existence
  claim no longer reads the file; a `contains` or `absent` claim on a non-text file now fails with a message. `--audit`
  has tests, including one over the real manifest.
- **CI and the release gate ran different checks (P5-05).** The 277-test CLI suite (`wrappers/python/tests/`) ran only in CI
  and is now a gate step. `npm run lint` ran nowhere and now runs in CI and in the gate through `tools/check_js_lint.sh`.
  The two Python pytest commands in `validate.yml` now pass `--fail-on-skip` (the CLI suite gets the flag through
  `wrappers/python/tests/conftest.py`, which loads the repository's `tests/conftest.py`). `tests/test_ci_parity.py` fails
  when a workflow pytest command lacks the flag, a workflow runs a tool the gate does not, or a workflow's pytest target
  is not covered by a gate step. The gate is now 26 checks.

### Changed

- **The JavaScript dependency audit now includes dev dependencies.** CI installs and runs eslint, so `npm audit` no
  longer passes `--omit=dev`. The release machine needs `npm` for the lint gate step; a missing `npm` is exit 3 and fails
  the gate.

### Added

- **Every gate tool is now tested in its failing state (P5-02).** `tests/test_gate_mutations.py` breaks one thing in
  a copy of the project per case, runs the real tool, and asserts its exit code, for `check_country_codes`,
  `check_version_consistency`, `sync_wrappers --check`, `enrich_field --check` (all four fields),
  `check_snapshot_freshness`, `check_registry_freshness` (the 180/181-day boundary), the five exporters' `--check`
  modes, `validate`, `check_mojibake` and `check_release_claims`. A meta-test fails when a tool joins the gate
  without a case or a written exemption. Before this, forcing `check_country_codes`, `check_version_consistency`,
  `sync_wrappers --check` or `enrich_field --check` to exit 0 left all 1,421 tests green.
- **Hygiene rule 10 (R10): a check that cannot fail is not a check.** `RELEASE_PATTERN.md` states it, cites P5-02, and
  names its enforcement (`tests/test_gate_mutations.py`). The numbering collides with ISO 3166's rules 10 to 19
  (P5-10); the rule is proposed to the siblings.
- **`tools/check_audit_table.py` derives `docs/AUDIT.md` from the tree (AD).** It reads `tools/`, the workflows and
  `run_gate()` and compares the `--check`, CI and Gate columns row by row; exit 0 match, 1 disagreement, 2 fatal. It is
  a gate step (the gate is now 24 checks) and a CI job. The table was true when the fifth-pass audit re-derived it;
  nothing kept it true.
- **`vendor_iso3166.py --check-upstream` (F31).** Lists the ISO 3166 tags with `git ls-remote --tags`, takes the highest
  stable `vX.Y.Z` and compares it with the vendored `source_version`: exit 0 current, 1 behind (or not an upstream tag),
  2 no stable tags or bad flags, 3 the tags could not be read. It is not a gate step (it needs the network, and a new
  upstream tag with no data change should not block a release). Against the vendored v1.8.0 it reports behind: ISO 3166
  v1.8.1 exists and changes no data.

### Notes

- **Fifth-pass audit complete.** 11 new findings (P5-01 through P5-11) and 2 meta-additions (R10, AD) identified; the
  report is `docs/audits/fifth-pass.md`. Queued for v1.9.1 through v1.9.5.

## Audit closure

Closed in this release: P5-02 (every gate tool is tested in its failing state), P5-05 (CI and the gate run the same
checks), P5-08 (`check_release_claims.py --audit` no longer crashes on Parquet files) and F31 (`--check-upstream`).
Added: rule 10 of `RELEASE_PATTERN.md` (R10) and `tools/check_audit_table.py` (AD).

Still open, queued for later releases: P5-01 (the stale `schema.json` in the Python wheel), P5-03 (country and currency
membership), P5-04 (numeric divergence between the wrappers), P5-06 (CRLF and the Windows manifest), P5-07 (`release.sh`
paths without tests), P5-09 (lookup precedence docs), P5-10 (rule numbering across the registries), P5-11
(`check_verification_doc.py` output and `--all`).

## Known limits

- **Nothing here ran on Windows.** `.gitattributes` still pins LF for only `*.csv`, `*.tsv` and `VERSION` (P5-06).
- **Rule 10 is enforced for gate steps that run `python3 tools/<name>` or `bash tools/<name>`.** CI-only checks that are not
  tools are covered by `tests/test_ci_parity.py`, not by the mutation tests. Six gate tools are exempt from a failing-state
  case, each with its evidence named in `tests/test_gate_mutations.py`.
- **The mutation sweep is not in the repository.** `proof_p5_02_mutation_sweep.py` ships with the release scripts; the
  meta-test is what lives in the tree.
- **`vendor_iso3166.py --check-upstream` is not a gate step.** It needs the network, and a new upstream tag with no data change
  would block a release.
- **The release machine now needs `npm`.** A missing `npm` is exit 3 in `check_js_lint.sh` and fails the gate.
- **The JavaScript audit now includes the eslint dependency tree**, so an advisory in a dev dependency can turn that step red.
- **The `1.9.0` entry in `tools/release_claims.json` asserts the old `--omit=dev` audit string**, so `check_release_claims.py 1.9.0`
  fails against this tree. The manifest is version-scoped and the gate checks only the target version.
- **The tool-name exit-code heuristic from the audit addendum was not turned into a per-code table.** Question D of the audit
  stays partly open.
