## What changed

Two ISO 4217 amendments, applied together. No schema changes.

### Amendment 179 — XAD added

Amendment 179 (PDF dated 2025-05-02, effective 2025-05-12) adds XAD,
the Arab Accounting Dinar (numeric 396, minor unit 2, Arab Monetary
Fund). The registry had `last_amendment_applied: 179` since v1.0.0
but never contained XAD. It is now in `non_iso.special_purpose`
beside XDR, XUA, and XSU, matching their shape: supranational unit
of account, no country, `iso_status: iso_code`.

### Amendment 180 — BGN withdrawn, BG joins EUR

Amendment 180 (PDF dated 2025-09-22, effective 2026-01-01) moves
Bulgaria to the euro. BGN is withdrawn:

- `code_lifetime: {"from": null, "to": "2026-01-01"}`
- `withdrawn_date: "2026-01-01"`, `replaced_by: "EUR"`,
  `conversion_rate: 1.95583`

BG joins EUR's `countries[]` with `relationship: issuing`. This is
the same shape as HRK, the previous euro changeover.

## The find: two amendments missed

The registry was created on 2026-07-29 (v1.0.0) at
`last_amendment_applied: 179`. It was wrong twice over:

- **Amendment 179's XAD was never applied.** The registry said 179
  but did not contain XAD.
- **Amendment 180 predated the registry's creation.** It was dated
  2025-09-22 and effective 2026-01-01, before v1.0.0 existed.

`last_verified: 2026-07-29` was false twice: not merely stale, but
wrong when written. The v1.7.15 amendment monitor (fixed to read
the SIX page) surfaced amendment 180 by returning 180 against a
registry that said 179. XAD was found separately, while preparing
this release.

The registry now says `last_amendment_applied: 180`,
`last_amendment_date: 2025-09-22`, `last_verified: 2026-10-15`.

## Known limits

### The commit boundary is one commit, not two

The data change and the tools/tests/docs catch-up landed as one
commit (`589cf8c`). The earlier `git add` had already staged the
files the tools and docs scripts wrote, so the second `git add -A`
found nothing to add. The tree is correct; only the split differs
from the plan.

### Five ISO 3166 items deferred to v1.8.1

From ISO 3166 v1.6.8:

1. **pyarrow pin.** `requirements-ci.txt` line 14 goes from
   `pyarrow>=26,<27` to `pyarrow==26.0.0` (item 5, ISO 3166).
2. **Orphan check comment filter.** `scripts/release.sh`
   `check_no_orphan_variables`: `grep -vE '^\s*#'` never matches
   `grep -n` output; change to `^[0-9]+:\s*#`.
3. **Mojibake signatures.** Two new patterns:
   `\xc3\xa2\xe2\x82\xac` (cp1252 em-dash prefix) and
   `\xef\xbf\xbd` (U+FFFD replacement character).
4. **Freshness docstring.** Two-mechanism framing
   (cross-reference vs. `review_by`).
5. **`[Unreleased]` rule.** Add to `RELEASE_PATTERN.md`. This repo
   already conforms (`release.sh` uses `grep -q "^## \[$VERSION\]"`,
   presence anywhere, not top-of-file).

### `update_from_iso.py --apply` still unconstrained

Writes `last_verified` without advancing the amendment (v1.8.2 per
the v1.7.15 verification doc).

### `schema.json` describes `meta.amendment_date` as "Effective date"

Under the v1.8.0 pick, the value is the PDF date (2025-09-22), not
the effective date (2026-01-01). Description correction deferred.

### `AAD` was a typo in planning notes

The registry entry is correct: `XAD`, numeric `396`. The v1.8.0
roadmap called it "AAD" in one place; no code or data carries that
string.
