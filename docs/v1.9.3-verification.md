## Summary

v1.9.3 closes P5-04 (the wrapper numeric contract) in the third-pass audit.
The four wrappers — Python, JavaScript, Go, Rust — produce identical numbers
for every input that mattered in the audit, and the divergences the audit
named (format vs to_minor, JPY ties, Go's `INT64_MIN`, non-finite spellings)
are fixed. ADR 0013 has six decisions (D1–D6), five rejected alternatives,
and six "verification owed" items. The contract test group has 83 vectors in
8 sub-groups; every expected value is recomputed by `tests/numeric_contract_oracle.py`,
which shares no code with any wrapper, so a vector cannot be edited to match
a wrapper's bug. The mutation sweep kills 29 of 29 mutants, all four controls
green. The clean-venv run of the full suite passes 1746 tests with `--fail-on-skip`.

## What changed

### D1 — Rounding mode: half away from zero, unchanged

The contract is already half away from zero in all four `to_minor`
implementations, documented in the code, and pinned by the issue #5
regression vector (`100.005 -> 10001`). Reversing it would be a numeric
break. The audit's premise — that the wrappers diverge on `to_minor` at
0.005, 0.015, 0.025, 0.125, 1.005, -0.005, -0.125 — was wrong; they agree
on all seven. `to_minor(1.005)` for USD is 100 in all four, because
`1.005 * 100` is `100.49999999999999` in a double. A decimal-string input
for all four wrappers is a v1.9.4+ item.

### D2 — Float semantics: one IEEE-double operation, then an exact round

For a finite float `x` and a currency with `n` minor units,
`p = x * 10^n` is computed once as a double, with `10^n` taken from an
exact table (`n <= 22`; the registry maximum is 18). The round is exact:
`t = trunc(p)`, `r = t + sign(p)` when `|p - t| >= 0.5`, else `t`. No
`floor(x + 0.5)` — in doubles `0.49999999999999994 + 0.5` is 1.0 and
above 2^52 the addition loses the half. The Python, Go, JS and Rust
implementations all follow the same algorithm.

### D3 — Overflow: an error when `|r| >= 2^63`

Int64 is the widest integer Go and Rust return; the rounded value is
itself a double that Python and JavaScript hold exactly; the 18-decimal
assets (ETH, BNB, DAI, USDP, FRAX, TUSD) need the whole range. The bound
is symmetric, so `INT64_MIN` is never a valid result. The error text
contains "amount too large". Python `Decimal` input is exempt — v1.9.0
(F28) made it exact and unbounded on purpose, and the CLI's `minor`
command depends on that. No other wrapper accepts a `Decimal`.

### D4 — Error shape: checked variants, additive

Python raises `OverflowError` (overflow) and keeps `ValueError` (non-finite).
JavaScript throws `RangeError` (overflow) and keeps `Error` (non-finite).
Go gains `ToMinorChecked(x) (int64, error)` with exported `ErrNonFinite`
and `ErrOverflow`; Rust gains `try_to_minor(x) -> Result<i64, MinorError>`.
The existing Go `ToMinor` and Rust `to_minor` keep their signatures and
panic on both errors, as they already do for NaN. `format` never calls
the panicking variants.

### D5 — `format` is derived from the same rounded value as `to_minor`

`format(x, ccy)` rounds exactly as `to_minor` does and prints that value.
Because `format` takes its digits from `r` and never narrows to int64,
`format` and `to_minor` cannot disagree on the rounded value, and
`format(10.0, ETH)` keeps working. NaN is `$nan`; infinities are `$inf`
and `$-inf`, lowercase in all four wrappers. `format(0.125, USD)` is
`$0.13` in Python, Go, Rust (it was `$0.12` in all three before; JS was
already `$0.13`). `format(1.005, USD)` is `$1.00` (JS was `$1.01`).

### D6 — Zero sign is preserved

A negative amount that rounds to zero keeps today's sign rule:
`format(-0.004, USD)` is `$-0.00`; `format(-0.4, JPY)` is `¥0`. This is
a legacy rule and is not endorsed; a v1.9.4 decision.

## Known limits

- **`to_minor(1.005, USD)` is 100, not 101.** `1.005 * 100` is
  `100.49999999999999` in a double. The `Decimal` path (Python only) gives
  101. A decimal-string input for all four wrappers is a v1.9.4+ item.
- **0-decimal currencies print without thousands separators.**
  `format(1234567.0, JPY)` is `¥1234567`, not `¥1,234,567`. Preserved from
  v1.9.2; the grouping policy is a v1.9.4 decision.
- **A negative amount that rounds to zero prints `$-0.00`.** Preserved;
  D6 marks it a legacy rule, not endorsed; a v1.9.4 decision.
- **18-decimal tokens are IEEE doubles.** `1.15` ETH formats as
  `Ξ1.149999999999999872` — the exact digits of the double, not the typed
  decimal. Identical across all four wrappers. A decimal-string input is
  a v1.9.4+ item.
- **Council Regulation 1103/97 Art. 5** is cited [Guess] in ADR 0013
  (from memory, not read this session).
- **Go on arm64 not run** (see Toolchain).
- **The `fifth-pass.md` → `third-pass.md` rename** is a v1.9.5 task; the
  collision is noted in ADR 0013.
