## What changed

F2 from the audit: `tools/check_cross_language.sh` reported a
wrapper suite whose toolchain was missing as `skipped` and exited
0, so the release gate could pass having run two of four suites.
The script was fail-open in two places, and the gate wrapped its
call in an existence guard that hid a third failure mode.

### Fixed — a missing toolchain is now a failure (F2a)

A suite that cannot run prints `NOT RUN (go not found)` and the
script exits 3, with a summary line naming every required suite
that did not run:
waiting for 2 workflow(s) on 779d1121 (timeout 300s, 60s for each to appear)
✓ all 2 workflow(s) for 779d1121 are completed success

Before v1.7.12, `poll_ci` returned success as soon as the first
workflow completed; the second was not required to have a run.
This release waited for both.

## Known limits

### The cross-language test uses stub toolchains

It proves the exit-code logic — a missing suite is exit 3, nothing
running is exit 2 — not that a real `go test` or `cargo test` ran.
The real suites are run by the gate itself (`bash
tools/check_cross_language.sh`, no flags) and by CI's wrapper
matrix. The stub tests and the real suites are complementary, not
substitutes.

### macOS bash 3.2 untested

The script was tested under bash 5.2.21. It uses no bash-4 features
(no associative arrays, no `${var,,}`), but the compatibility claim
is by inspection, not by test.

### The tests skip on Windows

`pytestmark = pytest.mark.skipif(sys.platform == "win32", …)` —
the tests drive a POSIX shell and stub toolchains via symlink. The
gate is POSIX-only anyway.

### `LC_ALL=C` on subprocess tests

Any future test that asserts on a system program's error message
must force the C locale in the subprocess environment. This release
learned that by failing on a French locale.
