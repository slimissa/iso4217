## What changed

F1 from the audit: `poll_ci` returned success on three paths where
it did not actually poll, so a commit whose CI never passed could
be tagged. Invariant 7 (*"tag only on green"*) was not enforced by
the script that claimed to enforce it.

### Fixed — `poll_ci` fails closed (F1a)

The three fail-open paths, all in `scripts/release.sh`:

- `gh` not installed — returned 0.
- `gh` returned no runs for the SHA — looped until the 5-minute
  timeout and then fell through to success.
- 5-minute timeout — fell off the loop and returned 0.

All three now fail. `gh` is a documented precondition and is
checked in `check_gh_available`, alongside `gh auth status`.
`poll_ci` requires a run for every workflow in `POLLED_WORKFLOWS`
within a 60-second grace period; a workflow still missing after
60 seconds means the push did not trigger it, which is a
misconfiguration, not a slow CI. The 5-minute wall-clock window
is now `--poll-timeout N` (default 300, positive integer only).

### Fixed — `gh` errors are no longer swallowed (F1b)

`2>/dev/null || echo ""` made an authentication or API failure
indistinguishable from "no run exists yet". Both looked like an
empty result and both looped to the timeout. `gh` errors now fail
immediately; only a successful empty result continues to poll.

### Closed as a side effect — early-success race

Requiring every workflow in `POLLED_WORKFLOWS` to have a run
closes the race where `version-and-hygiene.yml` completes before
`validate.yml`'s run has been created. Previously the function
returned success on the first complete set; now it waits for the
full set.

### The v1.7.11 divergence is closed

v1.7.11 shipped with a stub `docs/v1.7.11-verification.md` and
three commits named "Fill CI proof" that did not fill the proof.
The tag is immutable; the doc was corrected post-hoc. This doc
was completed in the same session that the release was cut, and
`tools/check_verification_doc.py` (added in a hygiene commit
between the two releases) is now part of the gate, so a stub
cannot ship again.

## Known limits

### The poll_ci fix is tested by extraction, not by a real release

`tests/test_release_poll_ci.py` cuts `poll_ci` out of the script
with an awk pattern and runs it in a subshell against stubbed
`gh`, `git`, and `sleep`. All three fail-open paths and the
early-success race are covered. What is not covered: the
integration with the actual `release.sh` main flow. A future
refactor of the script's structure would break the awk pattern
silently.

### `gh` is now a hard precondition

A developer without `gh` cannot cut a release locally. This is
the intent — invariant 7 says "no manual override, no force" —
but it is a real change to the release workflow.
