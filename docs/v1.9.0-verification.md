## What changed

The wrappers and the CLI: the npm package carries its data, the four wrappers fail the same way on malformed data, and the CLI stops crashing, stops echoing terminal escapes, and stops losing digits. This release also folds in F27 (cleanup), F30 (CI topology), records F29 as accepted, and re-vendors the ISO 3166 snapshot from v1.8.0. No registry data change; no schema change. The Python wrapper's API gains a `Decimal` overload.

### F6 — The npm package carries its data
`wrappers/javascript/package.json` names `iso4217.json` in its `files` field, but the file was not there and `npm pack` omitted it silently. An installed package could not find its data. `tools/sync_wrappers.py` now writes the file into the JavaScript directory, and `tests/test_js_package.py` runs `npm pack` and inspects the tarball.

### F13 — The four wrappers fail the same way on malformed data
Each wrapper now runs one strict validation pass over the parsed JSON before its typed decoding. Python raises `RegistryDataError` (a `ValueError`); JavaScript raises `RegistryDataError` (an `Error`); Go wraps `ErrMalformedRegistry` (visible via `errors.Is`); Rust stays `Err(String)` with the prefix `malformed registry data:` (a typed error enum would change `load()`'s signature, a breaking change in a minor release). All four name the same JSON path in the message. `docs/WRAPPER_VALIDATION.md` documents the contract. `tests/cross_language_consistency.json` gains 33 malformed registries to reject and 6 to accept, and every wrapper's suite reads it.

### F14 — `--registry <directory>` exits 3
`iso4217 --registry <dir>` was an uncaught `IsADirectoryError` traceback with exit 1. It now exits 3, and any other `OSError` on the registry path does the same.

### F15 — The CLI escapes control characters
`iso4217` echoed untrusted arguments into error messages. A crafted argument could set the terminal title or hide text. All error messages that echo input now escape the Unicode categories `Cc`, `Cf`, `Cs`, `Zl`, `Zp`. Argparse's own errors (bad values, unknown flags) go through `_SafeArgumentParser` with the same escaper. `repr()` was rejected because it would double the backslashes of a Windows path.

### F28 — Amounts are parsed as `Decimal`
`iso4217 minor` and `iso4217 major` parsed their argument via `float` and lost digits on amounts over 10^17. `Currency.to_minor()` and `Currency.format()` now accept a `Decimal` and convert it exactly. `int` and `float` behave as before. `iso4217 minor 1.005 USD` now returns `101` (correct decimal rounding) instead of `100`.

### F27 — Cleanup
- Unused imports removed: `hashlib` and `defaultdict` in `tools/update_from_iso.py`, the unused `jsonschema` import line in `tools/validate.py` (`SchemaError`, and `validate` with it), `overload` in `wrappers/python/iso4217.py`.
- `pyyaml` leaves the Python dev extras (nothing imports it) and `CONTRIBUTING.md` stops saying it is needed.
- `npm run lint` failed because `eslint` was not a dependency. It is now in `devDependencies`, exactly pinned at 10.12.0, with an `eslint.config.js` (ESLint 9 and later refuse to run without one).
- `tools/check_mojibake.py` scanned by suffix and skipped eight text files (`.gitattributes`, both `.gitignore`, `LICENSE`, `VERSION`, `MANIFEST.in`, `go.mod`, `go.sum`). It now scans them by name. The five `.parquet` outputs are binary and stay skipped.

### F30 — CI topology
In `validate.yml`, `validate-wrappers` no longer waits for `validate-json`; both start once their export and sync checks have passed. Dependency caches: pip (four jobs), npm and Go (their legs of the wrapper matrix), and Rust through a SHA-pinned `Swatinem/rust-cache` (because `dtolnay/rust-toolchain` has no `cache` input). Each cache names its dependency file via `cache-dependency-path`, because this repo has none of the default ones and the actions fail the step without one. The JavaScript audit now runs `npm audit --omit=dev`: it audits what ships, as before, instead of the linter's dependency tree.

### F29 — Accepted
The duplicated code in `tools/` (e.g., `load_registry`, `_atomic_write_binary`) is accepted by design. Each tool is deliberately self-contained so it can be read, run, and reviewed alone. Recorded in `CHANGELOG.md` and in `docs/AUDIT.md`.

### ISO 3166 re-vendor
`tools/iso3166_snapshot.json` re-vendored from ISO 3166 v1.8.0. Closes six releases of drift (v1.7.0 through v1.8.0), including the `independent` field correction in v1.7.3 and the `note` provenance fix in v1.7.4. `check_snapshot_freshness.py` did not catch this because it checks `review_by`, not source-version drift. That gap becomes F31, scheduled for v1.9.1.

## Known limits

Carried from the CHANGELOG's "Not in this release":

- **`iso4217 major` still prints via `float`** (`from_minor()` returns a float), so a very large minor amount loses digits on output. Its input is an exact `int`.
- **JavaScript cannot distinguish `2.0` from `2`**, so it accepts an integral float for `minor_units`; Python, Go and Rust reject it. `docs/WRAPPER_VALIDATION.md` says so; the shared fixture avoids it.
- **The wrappers do not detect duplicate currency codes** (the last one wins).
- **`check-wrapper-sync`'s `git diff` list omits `wrappers/python/iso4217.json`.** `sync_wrappers.py --check` covers it in CI and in the gate.
- **`docs/LAYERS.md` and `CONTRIBUTING.md` describe two or three wrapper copies, not four.** Neither was updated in this release.
- **`CONTRIBUTING.md` says "As of v1.8.4".** Nothing bumps that line.
- **Other unused imports remain, outside the F27 list:** `subprocess`, `Set` and `Tuple` in `tools/update_from_iso.py`, `from email import errors` in `tools/validate.py`, and ones in `enrich_field.py`, `export_aggregated.py` and `refresh_market_caps.py`. No check enforces it.
- **`npm run lint` is not run in CI**, and the Go leg of the matrix does not test the minimum `go 1.21` the module declares.
- **The release gate does not run `pytest wrappers/python/tests/`.** CI does (`validate.yml`); the gate runs `pytest tests/ -q`.
