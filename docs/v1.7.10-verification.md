## What changed

A test for the demo, and a fixture that reproduces the layout the
demo expects.

### Added — `tests/test_stores_200.py`

Runs `examples/stores-200/generate_facts.py` and `analyze.py` in a
temporary copy of the repository layout, then asserts specific
numbers from the output:

- Q1 — `508 rows for 200 stores` and `2,589,336,423 USD equivalents`
- Q1 — `Check: 200 of 200 stores have their (region, currency) pair in currencies_by_region.`
- Q4 — `7 stores, 36,531,068 USD equivalents (3.6% of the chain).`
- Q4 — `Joining on (region, currency) with '=' matches 193 of 200 stores`
- Q4 — `IS NOT DISTINCT FROM matches 200`
- Q5 — the 0-of-200 negative result
- Q6 — `6 of 22 currencies are pegged; they carry 13.2% of revenue.`

The module skips cleanly when `duckdb` or `pyarrow` is unavailable,
so the main suite still passes without the demo's dependencies.

### The fixture reproduces the repository layout

`generate_facts.py` reads its inputs from two directories above its
own cwd:

    REPO_ROOT = DEMO_DIR.parent.parent
    CURRENCIES_PARQUET = REPO_ROOT / "iso4217.parquet"
    COUNTRIES_PARQUET  = REPO_ROOT / "iso4217.countries.parquet"
    SNAPSHOT_PATH      = REPO_ROOT / "tools" / "iso3166_snapshot.json"

The test does not move the demo; it copies `examples/stores-200/`
into `tmp/examples/stores-200/`, then symlinks the registry artifacts
at `tmp/`. The demo runs unchanged.

### The fixture was corrected twice during development

First iteration: the five Parquet files were symlinked; the fixture
missed `tools/iso3166_snapshot.json`. Failure message named the file.

Second iteration: the five Parquet files *and* `tools/` as a
directory are symlinked. Symlinking `tools/` covers any future read
from there without a fixture change.

Both corrections were driven by the demo's own `FATAL: X not found`
error. The demo is authoritative about what it reads; the fixture
learned from it twice.

## Known limits

### The demo test asserts strings the demo prints

It does not recompute them. If the demo's arithmetic is wrong in the
same way its output is wrong, the test passes. What it catches: a
changed count, a dropped column, a broken join, a removed section, a
change in the demo's own words. That is the boundary — a regression
detector, not an oracle.

### The fixture covers what the demo reads today

It symlinks the five Parquet files and `tools/` as a directory. A
new read from elsewhere in the repository would still require a
fixture change, and the failure message (`FATAL: X not found`) names
the missing file. The pattern of the last three development
iterations is that the fixture learns the demo's reads by running
into them, one at a time.

### `stores.json` is written by `generate_facts.py` and committed

If a future change makes the demo non-deterministic in that file, the
in-repo copy will drift from what the demo produces. Current state:
byte-identical across runs, verified by the determinism check that
already exists for the registry's own exports.

### `facts.parquet` in `examples/stores-200/` remains untracked after a manual run

A `.gitignore` entry would be a separate one-line patch. Not folded
here because it is a change to `.gitignore`, not to the demo test,
and it deserves its own commit and its own CHANGELOG line.
