## What changed

Six audit findings (F5, F16, F18, F20, F22, F23), the amendment row
in the versioning policy, and the lessons from the ISO 10383
round-trip. Tooling, tests and documentation; no data change and
no schema change.

### The claims checker was silently passing bad claims

`tools/check_release_claims.py` read only `file` and `contains`. A
claim `{"file": ..., "absent": ...}` passed as "file exists",
whatever the file contained. Ported from ISO 10383 (`268cbd8`):
`absent`, an error on any unknown key, a missing file fails every
claim shape, and a top-level `"doc-facts"` list evaluated on every
run for every release. Tokens end at the open paren (`datetime.now(`,
`date.today(`, `time.time(`, `uuid.uuid4(`, `random.`) because
`datetime.now()` with empty parentheses is not a substring of
`datetime.now(timezone.utc)`. `tests/test_check_release_claims.py`
is new (15 tests including AST checks for aliased calls).

### `vendor_iso3166.py` read the clock

`--vendored-at` defaulted to `datetime.now(timezone.utc)`. It is now
required in write mode; the tool no longer reads the clock. A claim
of `datetime.now()` would not have caught it (see above); the
absence token in `doc-facts` now does.

### F5 — CONTRIBUTING regeneration listed four generators, not six

`release.sh` runs six. A contributor following step 3 got a red
`export_aggregated.py --check`. Step 3 is now release.sh's list in
order. `tests/test_contributing_regeneration.py` asserts the two
lists are equal and demonstrates the gap (old four steps leave
`export_aggregated.py --check` red).

### F16 — wrong ADR citations

`tools/validate.py` cited ADR 0006 for schema-version consistency
(ADR 0009) and ADR 0005 for numeric-code reuse (ADR 0008). Both
exist, so a resolve-only check missed them. Corrected; a new
`tests/test_adr_citations.py` pins all seven ADR citations the
tools make.

### F18 — the freshness check named itself wrong

`check_registry_freshness.py` printed `check_snapshot_freshness.py`
as its own name in `--help`, its docstring, its report header, and
the four Usage lines. Fixed; `PROVENANCE.md` section 8's tool name
also corrected. `tests/test_tool_self_names.py` is new: every
tool's `prog=` and Usage lines must name its own file.

### F20 — exit code 3 means "could not run"

New "Exit-code convention" section in `RELEASE_PATTERN.md`:
0 ok, 1 finding, 2 fatal or wrong input, 3 could not run (rule 7).
`check_verification_doc.py` and `check_readme_drift.py` used to
exit 3 for missing local input (2); both now exit 2.
`check_readme_drift.py` with git absent was an uncaught traceback
(exit 1, reads as drift); it now exits 3.

### F22 — PROVENANCE was not per-field

46 distinct field names in `iso4217.json`; 19 were named in
`PROVENANCE.md` in backticks. New section 9: a per-field table
(field, where, source, refresh trigger, checked by).
`tools/check_provenance.py` fails when a field has no row, a row
names a missing field, a cell is empty, or "Checked by" names a
file that does not exist. CI job and gate step; gate is now 23
steps (F22).

### F23 — JOINS.md omitted the region/subregion edge

`export_aggregated.py` reads `region` and `subregion` from the
vendored snapshot. `JOINS.md` said "Planned: none. The edge is
complete." It now names the edge, the snapshot's reliance on
`countries.active` only (SK and AI appear in the withdrawn list),
the null region on XK and TW, and the `vendor_iso3166.py --check`
that covers byte identity.

### Versioning policy

An ISO amendment that changes which currencies are active is
**Minor**, not Patch. `CONTRIBUTING.md` and `README.md`'s Minor
bullet now agree; `tests/test_versioning_policy.py` asserts both.

### ISO 10383 lessons

`RELEASE_PATTERN.md` gains two sections: no `grep` on JSON (use
`json.loads` and string comparison; escaped characters in JSON
defeat `grep -F`), and "Asserting on prose" (normalize whitespace
before checking docstring or README prose; a line break breaks a
substring test). Two docstring assertions in
`tests/test_check_mojibake.py` now normalize first.

### Four items deferred to v1.8.4

The consolidated pattern-document scope had 13 items; the ZIP
contained 9. Four are text-only, one is one line:

  (Category A producers, Category B validators, Category C

  and gate).
- **A11** — CURATED-vs-AGGREGATED `--check` distinction in
  `RELEASE_PATTERN.md` (CURATED compares bytes, AGGREGATED compares
  content; from ISO 3166 `3bc1516`).
- **A12** — Tag-message verification section (trailing newline,
  three exit codes for `diff -q`, `--cleanup=verbatim` mandatory;
  from ISO 3166 v1.7.0).
- **A13** — `scripts/release.sh`: `--cleanup=whitespace` →
  `--cleanup=verbatim`. One line.

v1.8.4 closes all four.

### A5 and A9 initially failed on missing `--date`

Both scripts require `--date` for the review-history entry. The
roadmap's commit-sequence table showed the flag; the operator's
invocation omitted it. The scripts refused with argparse usage
errors and wrote nothing. B ran against the tree as it was (A6, A7,
A8 applied; A5, A9 not), and the claims assertions for what A5
and A9 write failed at `check_release_claims.py` time. Rerun with
`--date $(date -u +%Y-%m-%d)` fixed it.

This is the fourth release in a row where the pipeline caught a
genuine intent-versus-tree gap (v1.7.9, v1.8.0, v1.8.1, v1.8.3).
Operator-hygiene note for future releases: **roadmap invocations
must be copied whole, flags included.**

### ISO 10383's absence claims use the empty-paren form

The token gap A1 closed on 4217's side exists in ISO 10383's
manifest. The tokens must end at the open paren
(`datetime.now(`, not `datetime.now()`), or they pass vacuously
against `datetime.now(timezone.utc)`. Flagged to the builder.
