The gate uses per-check capture (`run_gate_step`), not a brace
group. Each check's exit code is read individually; `GATE_FAILED`
is set on any failure; the gate exits after all checks complete.
Unlike a brace group on the left of `||`, this shape catches a
mid-block failure — a detail that surfaced in the ISO 3166
exchange on v1.6.6 and confirmed this side is not exposed to the
same bug.

## What changed since v1.7.1

**Fixed:**

  behavior was a bug in the source, not a design. Reciprocal fix
  landed in `d5d8425`.

**Added:**
- `RELEASE_PATTERN.md` operator-hygiene rule 6b — "the commit is
  not the working tree." Names `3687bc2` and ISO 3166 v1.6.4.
- `RELEASE_PATTERN.md` "Review history format" section — the
  attribution convention from the ISO 10383 exchange.
- `tools/check_release_claims.py` docstring — the gate-only design
  rationale.
- `RELEASE_PATTERN.md` invariant 5 — softened to allow gate-only
  checks whose inputs are version-scoped.

## Known gaps

- `code_lifetime.from` remains `null` for all 135 withdrawn entries
- `axes.json` declared but not consumed by `check_version_consistency.py`
- Manifest precondition not yet adopted. A `check_manifest_has_version`
  precondition would fail on the missing 1.7.2 entry two seconds in
  instead of after version bump and artifact regeneration. Recommended
  for v1.7.3.
- The `release_claims.json` entries could be audited for dropped
  claims — the ISO 3166 exchange surfaced a case where a claim was
  edited to pass rather than a fix landing. No equivalent drop
  detected on 4217's side, but the audit is a v1.7.3 item.
