## What changed

Five tooling and documentation fixes from the ISO 3166 v1.6.8 review.
No data changes; no schema changes.

### Fixed — orphan check ignored comments (item 2)

`scripts/release.sh`'s `check_no_orphan_variables` filtered comments
out of `grep -n` output with `grep -vE '^\s*#'`. Because every line
of `grep -n` output starts with `N:`, the pattern matched nothing:
a `$VAR` named in a comment aborted the release as an undefined
variable. Filter is now `^[0-9]+:\s*#`. Five new tests in
`tests/test_release_hygiene.py::TestOrphanCheck`. A trailing comment
on a code line still fires, and a test pins that limitation.

### Fixed — mojibake signatures and docstring (item 3)

`tools/check_mojibake.py` gained two signatures:

- `\xc3\xa2\xe2\x82\xac` — a-circumflex followed by the euro sign,
  what Windows-1252 makes of the first two bytes shared by em dash,
  en dash, curly quotes, ellipsis, and bullet.
- `\xef\xbf\xbd` — the U+FFFD replacement character.

The docstring described U+201A as a corrupted em dash; it is what
Windows-1252 leaves from a euro sign. `tests/test_check_mojibake.py`
is new — the checker had no tests until this release.

### Changed — pyarrow pinned exactly (item 1)

`requirements-ci.txt`: `pyarrow>=26,<27` → `pyarrow==26.0.0`. Every
Parquet footer records the pyarrow version that wrote it. A range
would let a different pyarrow produce different bytes for the same
logical content, and the `--check` modes would fail on the next
machine that made the other choice.

`tests/test_ci_supply_chain.py` exempts pyarrow from the
lower-and-upper-bound rule and adds an assertion that pyarrow is
exact-pinned.

**A2b was a no-op.** The five committed Parquet files were already
written by pyarrow 26.0.0; regeneration produced identical bytes.

### Changed — freshness docstring names two mechanisms (item 4)

`tools/check_snapshot_freshness.py`'s docstring now states that
scheduled re-verification (its own `review_by` check) and
cross-reference validation (the consumer's check against a held
value) are two mechanisms, not one. Ends: "Neither replaces the
other. Do not merge them."

### Changed — `[Unreleased]` rule (item 5)

New section in `RELEASE_PATTERN.md`: `CHANGELOG.md` may carry an
`[Unreleased]` heading at the top at release time. Four consumers
were verified (the `release.sh` grep, the staged-heading rewrite,
the tag-message awk, and `check_version_consistency.py`). One
qualifier: among dated headings, the first must still equal
`VERSION` before the release script bumps it.

## The gate caught a gap on the first attempt
The first release.sh 1.8.1 attempt failed at check_release_claims.py:

  [FAIL] RELEASE_PATTERN.md does not contain 'The `[Unreleased]` rule'

Cause: the A5 script refused the date 2026-10-17 as "in the future"
(the sandbox clock was ahead of UTC), and wrote nothing. The B commit's
claims entry asserted a section that never landed.

Fix: A5 reran with --date 2026-10-16 (the true UTC date). The section
landed as commit 0e7db99. The release reran cleanly.

Third release in a row where check_release_claims.py caught a gap between
a claim and the tree (v1.7.9, v1.8.0, v1.8.1).

This is what `check_release_claims.py` exists for: a claim that
describes intent rather than state is a contract with nothing to
enforce.

## Known limits

### Transient red on the `[Unreleased]` commit

`0e7db99` (the `[Unreleased]` rule commit) had a `Validate Registry`
run whose `Validate iso4217.json` and `Validate wrapper` jobs failed.
A rerun of the same commit went green with no change. Attributed to
a transient runner or network condition; the tag `v1.8.1` is on
`7885a2c`, whose `Validate Registry` was green.

### Two more wrong docstring entries in `check_mojibake.py`

Claude's §4 in the roadmap. The entry attributed to ✅ is the
Latin-1 corruption of the Mathematical Operators block (infinity
sign, summation); the entry attributed to box drawing is the
Latin-1 corruption of General Punctuation (em dash, en dash, curly
quotes, ellipsis, bullet). Box drawing corrupts to a different
prefix that no pattern covers. Four lines, same file. Deferred.

### Trailing-comment orphans still fire

`echo ok # $FAKE_VAR` in `release.sh` still triggers the check.
The item-2 fix covers comment-only lines; a test pins the limitation.

### The release machine's pyarrow is unconstrained

`release.sh` regenerates locally and nothing in the release path
installs `requirements-ci.txt`. The pin constrains CI and the venv;
a check that the release machine's installed pyarrow equals the pin
is a candidate for a future release gate.

### `examples/stores-200/requirements.txt` still says `pyarrow>=14`

The demo is outside CI. No fix scheduled.

### The v1.8.0 commit-boundary slip (carried from v1.8.0)

The Amendment 179/180 data change and the tools/tests/docs catch-up
landed as one commit (`589cf8c`) rather than the planned two.
