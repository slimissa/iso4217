## 8.14 — Release pipeline

Fourteen gate checks, all green. Poll confirmed every workflow
for the release commit.

This release was the first to run `pytest` inside the gate — a
v1.7.5 addition. Prior releases ran the fast convention checks
only; pytest was a CI-only check. The addition came from a
v1.7.5 pre-release incident: a stale test assertion was caught by
CI but not by the local gate, so a release commit landed on `main`
with a red CI before the tag was created.

## What changed since v1.7.4

**Fixed:**
- `CHANGELOG.md` — the v1.5.3 heading carried the placeholder
  `2026-09-XX` instead of the tag's actual date. Corrected to
  `2026-09-18`. The `export_aggregated.py --check` note about the
  placeholder no longer fires.
- `docs/decisions/numeric-code-reuse.md` — renumbered from
  ADR 0005 to ADR 0008. The number 0005 was already claimed by
  `note-source-split.md` (v1.6.0).
- `docs/decisions/schema-version-consistency.md` — renumbered from
  ADR 0006 to ADR 0009. The number 0006 was already claimed by
  `code-lifetime.md` (v1.6.0).
- `tools/check_registry_freshness.py` — allows up to one day of
  timezone skew. CI runs on UTC; a maintainer whose local time is
  ahead of UTC can write `meta.updated` to what the runner sees as
  "tomorrow." A one-day skew is a timezone artifact, not a data
  error. Only dates two or more days in the future fail.

**Added:**
- `python3 -m pytest tests/ -q` as the fourteenth check in
  `scripts/release.sh`'s gate. Every check that runs in CI's fast
  workflow now runs in the release script.
- `tests/test_export_aggregated.py::TestCoverageTimelineRealData::test_1_5_3_has_real_date`
  replaces the placeholder-date test. Asserts the fixed date and
  the absence of a stderr note.

## Two incidents on the path to v1.7.5

Both caught by the release script's poll before the tag was
created. Neither is visible in the shipped artifact.

**Incident 1 — stale test after the CHANGELOG fix.** The
placeholder-date fix invalidated a test that asserted the
placeholder behavior. CI's pytest job caught it; the release
script's gate did not, because pytest was not yet in the gate.
Fixed by adding pytest to the gate.

**Incident 2 — timezone skew in a date check.** `meta.updated` was
set from the maintainer's local clock (Tunisia, UTC+1) to
`2026-10-07`. The CI runner executed at `2026-10-06T23:19Z` and
saw the registry as one day in the future. Fixed by adding a
one-day tolerance to `check_registry_freshness.py`.

Both fixes landed as separate commits between the release attempt
and the tag, which is the correct shape: the tag lands on a
verified state, not on the first attempt.
