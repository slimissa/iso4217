## Details

### 8.4.4 — CLI vs. committed TSV

`iso4217 list --active --tsv` was compared byte-for-byte against the
active rows of the committed `iso4217.tsv`. No differences.

### 8.4.5 — CLI help output

Verified:

- `iso4217 --help` lists all eight subcommands, including `lookup` and
  `validate`
- `iso4217 lookup --help` ends with an `Example:` section
- `iso4217 lookup --help` ends with an `Exit codes:` section naming the
  four documented codes

Note: an earlier script run reported FAIL on the first two checks
because it matched subcommand names against a 2-space indent. `argparse`
indents subcommands with 4 spaces. The script was corrected and the
checks pass.

### 8.5 — README vs. CLI subcommands

The eight subcommand names extracted from `README.md` were compared as
a sorted set against the eight subcommand names in `iso4217 --help`
output. The sets are identical:

    format, info, list, lookup, major, minor, peg, validate

### Deferred checks

The following checks are deferred to a machine that has Windows and
LibreOffice installed:

- **Excel encoding**: `iso4217.excel.csv` in Excel on Windows, no
  encoding prompt, `¥` / `€` / `د.ك` render correctly.
- **CR bytes**: PowerShell byte scan of all four files, expecting zero
  CR bytes.
- **BOM policy**: PowerShell BOM check, expecting BOM only in
  `iso4217.excel.csv`.
- **LibreOffice European locale**: `iso4217.european.csv` opens in
  LibreOffice with FR or DE locale without an import dialog.

These will be run and recorded in a follow-up commit when the Windows
environment is available.

## Known remaining gaps

- **The v1.5.0 tag ships a wheel without data files.** The `build_py`
  override that fixes this landed after the tag, in commit `d718d21`.

- **PyPI / npm / crates.io publication.** The packages are not yet
  published. Verification used a locally built wheel.
- **`standard` field on every JSON entry.** Deferred to v1.6.0; see
  `docs/decisions/v1.6.0-candidates.md`.
