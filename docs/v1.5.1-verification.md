## Details

### 8.4.4 — CLI vs. committed TSV

`iso4217 list --active --tsv` was compared byte-for-byte against the
active rows of the committed `iso4217.tsv`. No differences.

This is the cross-check that proves the CLI's column order matches the
export's. It catches drift between the CLI's `LOOKUP_FIELDS` and
`tools/export_csv.py`'s `COLUMNS`.

### 8.4.5 — CLI help output

Verified:

- `iso4217 --help` lists `lookup` and `validate` among the subcommands
- `iso4217 lookup --help` ends with an `Example:` section
- `iso4217 lookup --help` ends with an `Exit codes:` section naming the
  four documented codes

### 8.5 — README vs. CLI subcommands

The eight subcommand names extracted from `README.md` were compared as
a sorted set against the eight subcommand names in `iso4217 --help`
output. The sets are identical:

    format, info, list, lookup, major, minor, peg, validate

### Windows-specific checks

- **Excel encoding**: `iso4217.excel.csv` opened in Excel on Windows
  without an encoding prompt. The `¥`, `€`, and `د.ك` symbols rendered
  correctly in the symbol column for JPY, EUR, and KWD respectively.
- **CR bytes**: 0 CR bytes in all four files. LF-only, as designed.
- **BOM policy**: only `iso4217.excel.csv` has the UTF-8 BOM
  (`EF BB BF`); the other three have no BOM.

## Known remaining gaps

- **The v1.5.0 tag ships a wheel that lacks `iso4217.json` and
  `schema.json`.** The `build_py` override that fixes this landed after
  the tag, in commit `d718d21`. Users installing from a wheel built at
  the `v1.5.0` tag will get a CLI that cannot resolve its data file.
  Users installing from the v1.5.1 tag or from `main` are unaffected.
- **PyPI / npm / crates.io publication.** The packages are not yet
  published. The v1.5.1 verification used a locally built wheel.
- **`standard` field on every JSON entry.** Deferred to v1.6.0; see
  `docs/decisions/v1.6.0-candidates.md`.
