## Details

### 8.4.4 — CLI vs. committed TSV

`iso4217 list --active --tsv` was compared byte-for-byte against the
active rows of the committed `iso4217.tsv`. No differences.

### 8.4.5 — CLI help output

Verified:

- `iso4217 --help` lists all eight subcommands, including `lookup` and
  `validate`
- `iso4217 lookup --help` ends with an `Example:` section
- `iso4217 lookup --help` ends with an `Exit codes:` section naming the
  four documented codes

Note: an earlier script run reported FAIL on the first two checks
because it matched subcommand names against a 2-space indent. `argparse`
indents subcommands with 4 spaces. The script was corrected and the
checks pass.

### 8.5 — README vs. CLI subcommands

The eight subcommand names extracted from `README.md` were compared as
a sorted set against the eight subcommand names in `iso4217 --help`
output. The sets are identical:

    format, info, list, lookup, major, minor, peg, validate

### Windows and Excel verification

The Windows-only checks were run on a fresh `git clone` of the v1.5.1
tag (`c98a840`) on Windows 10 build 26200.9457, using Git for Windows
with default `core.autocrlf`. The files were read from WSL at
`/mnt/c/Users/WIKI/Documents/iso4217`.

**BOM policy** — all four files correct:

    iso4217.csv            BOM = False  ✓
    iso4217.excel.csv      BOM = True   ✓
    iso4217.european.csv   BOM = False  ✓
    iso4217.tsv            BOM = False  ✓

**CR bytes** — zero in all four files:

    iso4217.csv            CR bytes = 0  ✓
    iso4217.excel.csv      CR bytes = 0  ✓
    iso4217.european.csv   CR bytes = 0  ✓
    iso4217.tsv            CR bytes = 0  ✓

**SHA-256 match** — all four files match the Linux manifest byte for
byte. The Windows clone preserved every byte including the BOM and the
LF endings:

    iso4217.csv            a5bf9dc6d1b064762937fba3f34c72a412530be0733ad7aea577f8e6356183f7
    iso4217.excel.csv      4afbd905ce24a45bd65915e2317438071ee41fc534ea61969b81486fac7c90cd
    iso4217.european.csv   a5a671a93baef84e330781c0686df0199dfe1727142e15a32d961fc8a9aad4e6
    iso4217.tsv            0e56f6821237334acd718f436a34f4ae20518352578092bdb9ea8fc0de89a2e9

This confirms the `.gitattributes` rules for `*.csv` and `*.tsv`
correctly force `eol=lf` on a Windows clone, even with
`core.autocrlf=true` (the default on Windows). The rule is working as
designed.

**Excel encoding** — `iso4217.excel.csv` opened in Excel 365 by
double-click on Windows 10. No Text Import Wizard appeared, no encoding
prompt. All non-ASCII symbols rendered correctly, verified by visual
inspection:

    AED  د.إ     ✓
    AFN  ؋       ✓
    BGN  лв      ✓
    EUR  €       ✓
    INR  ₹       ✓
    IRR  ﷼       ✓
    JPY  ¥       ✓
    KWD  د.ك     ✓
    MUR  ₨       ✓

The BOM is doing exactly what it was added for: Excel auto-detected
UTF-8 without any manual encoding selection.

**LibreOffice European locale** — not tested. LibreOffice was not
installed on the Windows environment. The CSV structure is already
verified by the byte checks above; the LibreOffice check is a
convenience verification, not a correctness one.

### Status

All v1.5.1 verification checks pass. The deferred items are now closed.
v1.5.1 is fully verified against both Linux and Windows.
