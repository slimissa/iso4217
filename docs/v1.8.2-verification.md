## What changed

Six items from the ISO 3166 v1.6.9 exchange, plus one data
correction the exchange surfaced. The only data change is the
vendored snapshot.

### Fixed — the vendored snapshot was not a copy of any tag

`tools/iso3166_snapshot.json` was labelled v1.6.7, but it was not
byte-identical to v1.6.7, v1.6.8, or v1.6.9. BG's `currency_codes`
had been edited by hand to `["EUR"]` at v1.8.0, before ISO 3166
shipped that change in v1.6.9. The file looked right — BG was
indeed under EUR by v1.6.9 — but its provenance was false: no
tag produced those bytes.

This is the exact failure mode rule 8 (added in this release)
exists to prevent: a committed artifact whose output cannot be
regenerated, whose bugs are invisible. The pre-flight
`vendor_iso3166.py --check` dry-run named it:

committed snapshot vs ISO 3166 v1.6.7: DIFFERENT (expected: it was edited by hand)
first differing byte at offset 18729
1 entry differ: active/BG: currency_codes
text


A1 re-vendors from v1.6.9 (byte-identical, 238631 bytes). Against
the old file: BG `last_verified` and `note`, snapshot
`meta.version` 1.6.7 → 1.6.9 and `updated`. No currency code
changes; `check_country_codes.py` is unaffected.

### Added — `tools/vendor_iso3166.py` with `--check`

The tool copies the ISO 3166 source tag byte-for-byte. `--check`
calls the same `build_vendored()` function the write path calls —
no separate byte-compare logic, so preservation branches are
exercised on every invocation. Fetches the tag from
raw.githubusercontent.com with three attempts; exit 3 if it cannot
reach (rule 7: not a pass). CI job
"ISO 3166 snapshot matches its source" runs it;
`release.sh` runs it as a gate step.

### Added — `enrich_field.py --check` in CI and the gate

Four fields (`classification`, `code_lifetime`, `numeric_reused`,
`source_url`), each a separate job in `version-and-hygiene.yml`
and a separate gate step. Item 6b from the ISO 3166 exchange.
`--field` is now documented as required in the tool's docstring.

### Fixed — `regenerate_artifacts` swallowed generator failures (item 7b)

`release.sh`'s `regenerate_artifacts` wrote each generator as
`python3 tools/X.py >/dev/null && info "✓ ..."`. A command failing
in a non-final position of an `&&` list does not trigger `set -e`:
the script printed "reached line 2" and exited 0 in a three-line
reproduction. The first five generators could fail without
stopping the release; only `sync_wrappers.py` propagated. Now
`|| fail "X.py exited non-zero"` per generator, and a new test
class runs the real function against a failing stand-in.

### Added — `RELEASE_PATTERN.md`

- **Invariant 5 amendment** — the same rule (every CI check in the
  gate) covers the commands that produce what the release commits.
  Sourced from ISO 3166 v1.6.9 (`94350d6`).
- **Rule 8, "Every tool proves its own reachability"** — a tool
  with no `--check` or smoke invocation in CI may have unreachable
  code paths. Reference case: ISO 3166's `gen_iso4217_snapshot.py`
  at `07e103f`, `NameError` in write and `--check` mode alike.
  This repo's own instance: `enrich_field.py --check` ran nowhere
  before this release; the vendored snapshot had no tool at all.
- **"Version-pinned byte outputs"** section and its settings
  corollary. Sourced from ISO 3166 v1.6.8 (`8902ba6`, pin
  `aa784da`) and `4b272e5` (the corollary). The parent rule text
  is the one ISO 10383 proposed: `--check` compares bytes; the
  render must not read the clock, the OS, or an unpinned
  dependency.

### Fixed — `tools/check_mojibake.py` docstring

The check-mark entry is Latin-1 corruption of the Mathematical
Operators block (infinity sign, summation); the box-drawing entry
is Latin-1 corruption of General Punctuation. Box drawing corrupts
to a different prefix that no pattern covers. Tests compute the
provenance rather than asserting literals.

## Known limits

### Transient red on `2e89ce3`

The `tools/vendor_iso3166.py` commit had a `Validate Registry` run
whose three wrapper jobs (go, rust, python) failed; the javascript
wrapper passed and `Validate iso4217.json` passed. A rerun of the
same commit went green on all ten jobs with no change. The A2
commit `8fa0e75` on top of A1 was green on both workflows.
Attributed to a transient GitHub Actions or package-registry
condition; the tree at A1 is fine.

### `vendor_iso3166.py --check` requires network access

The gate therefore requires GitHub reachability. A release run
offline fails the gate with exit 3, which is correct behaviour for
rule 7 (a check that cannot run is not a pass). Only `--re-vendor`
writes; `--check` fetches and compares.

### Release-machine pyarrow still unconstrained (carried from v1.8.1)

`release.sh` regenerates locally and nothing in the release path
installs `requirements-ci.txt`. The pin constrains CI and the venv;
a check that the release machine's installed pyarrow equals the
pin is a candidate for a future release gate.

### Trailing-comment orphans still fire (carried from v1.8.1)

`echo ok # $FAKE_VAR` still triggers the orphan check. The item-2
fix from v1.8.1 covers comment-only lines; a test pins the
limitation.

### The vendored snapshot's provenance history is now clean

The v1.8.0 meta note ("Re-vendored from v1.6.7 … BG currency_codes
is ["EUR"]") described a file that never existed. This release
replaces both the note and the file. The history is now: hand-edit
at v1.8.0, honest re-vendor at v1.8.2.
