## What changed since v1.6.0

**Tooling:**
- `tools/check_mojibake.py` — signature set extended from three literal
  byte sequences to four patterns, the fourth being a range check
  covering every Latin-1 accented-character round-trip. Added `.sql`
  and `.html` to scan suffixes. Added `# mojibake-scan: skip` marker.
- `tools/check_country_codes.py` — new. Verifies every
  `countries[].code` resolves in the ISO 3166 snapshot. Supports
  `--refresh-from` for coordinated snapshot updates.

**Contract:**
- `axes.json` — new. Declares the two version axes (registry, schema)
  and the 11 sites that carry them, plus the eight extractors that
  read those sites. Not yet read by `check_version_consistency.py`;
  the refactor that makes it data-driven waits for a third
  implementation.

**Cross-registry:**
- `tools/iso3166_snapshot.json` — vendored byte-for-byte copy of
  ISO 3166 v1.5.2's `iso3166.json`. This is 4217's first vendored
  snapshot and the second cross-registry join in the QuantOS
  ecosystem (Exchange Calendar → ISO 3166 was the first).
- CI job `check-country-codes`.

**Documentation:**
- README "Consumed by" table gains an ISO 3166 row naming the
  vendored version.
- `docs/LAYERS.md` gains a "Vendored snapshots" subsection under
  CURATED.

## Known gaps

- `code_lifetime.from` remains `null` for all 135 withdrawn entries.
  Unchanged from v1.6.0. No ISO assignment date is documented for any
  of them. See `docs/PROVENANCE.md`.
- The `axes.json` file is declared but not yet consumed. The refactor
  of `check_version_consistency.py` to read it waits for ISO 10383's
  version check to ship, making three implementations.
- The `is_independent` default divergence between Python/CSV (`False`)
  and JS/Go/Rust (`True`) noted in earlier reviews remains. Latent
  because no test vector omits the field. Deferred.
