## 8.9 — Release pipeline

The `poll_ci` fix landed in `1f38fb4`. The v1.6.2 release was the
first to exercise it:

    == Polling CI ==
      waiting for CI on 8265ae5e (up to 5 minutes)
      ✓ all workflows for 8265ae5e are completed success

Previous versions used `head -1` and confirmed only the first run
for the SHA. v1.6.2 verifies every workflow that triggers on the
release commit.

Two additional preflight checks landed in the same commit:

- `check_head_at_origin` — fetches `origin/main` and refuses if
  local HEAD differs
- `check_workflows_covered` — asserts every per-push workflow in
  `.github/workflows/` is in `POLLED_WORKFLOWS`

## What changed since v1.6.1

**Release script:**
- Polls every workflow instead of `head -1`
- Refuses on `HEAD != origin/main` (with fetch)
- Verifies workflow coverage against the directory

**Validator:**
- `UNUSUAL_MINOR_UNITS_COUNT` gated on `classification == "circulating"`
- Warning count 27 → 26

**Tooling:**
- `tools/iso3166_snapshot.meta.json` — vendoring metadata for the
  ISO 3166 snapshot, carrying `review_by` and `refresh_cadence`

**Documentation:**
- `docs/decisions/numeric-code-reuse.md` — ADR 0005

**Fixed:**
- Orphaned `from wrappers.python.iso4217 import active` import in
  `tools/validate.py` removed
