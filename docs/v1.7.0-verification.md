## 8.4 — Validation

  ✅ VALIDATION PASSED
text


Full run emits 0 errors and 26 warnings. The count dropped from 27
to 26 because `SCHEMA_VERSION_MISMATCH` was removed in v1.7.0. That
warning fired on every run since v1.6.0 because `validate.py`
hardcoded a schema version that had drifted from `1.4.0`. Version
agreement is now owned solely by `check_version_consistency.py`;
`validate.py` reads the schema's shape from `schema.json` and
verifies data integrity. See ADR 0006.

The remaining 26 warnings are:

- 25 `REVALUATION_CHAIN_NUMERIC_REUSE` — one per revaluation chain
  where two or more withdrawn currencies share a numeric code
- 1 `NUMERIC_CODE_REUSE` — the active/withdrawn counterpart

Both classes are documented as permanent, expected signals in
ADR 0005.

## What changed since v1.6.3

**Fixed:**
- `tools/validate.py` — removed the hardcoded schema version check.
  Warning count 27 → 26.
- Wrapper `is_independent` default aligned across Python, JavaScript,
  Go, and Rust. Absent field now reads as `False` in all four,
  matching the CSV export. Previously JS/Go/Rust defaulted to `True`.

**Added:**
- `docs/decisions/schema-version-consistency.md` — ADR 0006.
- `RELEASE_PATTERN.md` at repo root. Documents the eight invariants
  shared across four `release.sh` implementations, the two shapes of
  the post-rebuild verify step, the registry-vs-snapshot freshness
  distinction, the wrapper-copy test question, tag immutability,
  five operator hygiene rules, and the mojibake self-trigger rule.
  Reviewed by ISO 4217 and ISO 3166.

**Cross-wrapper alignment:**

The `is_independent` divergence was latent through three review
cycles. It surfaced when the shared fixture gained a `DEM` vector
that asserted the aligned default. The three wrappers that had
defaulted to `True` (JS, Go, Rust) failed the fixture, and the
fixed versions passed. The fixture is the guard; the alignment
closes the bug.
